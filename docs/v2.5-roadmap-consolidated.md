## 二、统一波次（最大公约数 + 一处分歧）

| 波次 | 内容 | 备注 |
|---|---|---|
| **W1 并行双线** | 线 A = 批次 2 结构收敛（推送基类+路由表）；线 B = 文案级零冲突小件（连续话术、活动开始提醒、周报趋势——口径已就绪） | 两线零文件冲突可并行 |
| **W2** | toast 渠道（#3）→ 免打扰（#4）→ 回满即推 ⭐ | 回满即推走新推送基架是评审 B 的排序理由 |
| **W3 插队小件** | 倒计时（#6）、纯净包（#7）、数据自愈提示（#7 血肉） | 随时插入 |
| **W4 壳工程批** | 批次 3 三僵尸 + 数据外置 + 托盘总览（#6 血肉）+ **改名**（如裁决）一次重编译 | 改名清单已备好 |
| **W5 验证后** | 小号 lite 第 0 期 → 主键迁移；重置面板（设计稿先行） | |

**⚠ 唯一排期分歧（需拍板）**：回满即推放 W1 快赢包先行（评审 A：最佳单品）还是 W2 等批次 2 新基架（评审 B）。事实核查：推送出口已是 push_all 统一汇聚点，回满即推**不新增渠道、不强依赖批次 2**；它真正的新东西是「到点触发器 + 复核」。两个都能自圆其说，默认建议：**独立单元先行**（含两修正 + 临时免打扰占位），理由是它价值密度最高且不受基架排期拖累。

## 三、协调制度（两会话共同的警告，升格执行）

- **同一时间窗只指定一个写者**（今天已实测两次并行回写互吞未提交改动）；
- 被挤的一方转出**侦察/设计文档**而不是施工；
- 排期由用户统一指定；验收节奏不变：备份 → 实施 → 截图 → 套件 → 停等。
